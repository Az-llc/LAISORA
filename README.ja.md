AIエージェントが次々とコマンドを実行し、コードを書き換えていく。そのログを眺めていても、何をしているのか、なぜ必要なのかまでは分からない。私自身、そんな場面が増えました。

それなら、普段は「何を実現したいか」「どう進めるか」の対話を読みやすくしたい。詳しく知りたいときは、エージェントに説明を求めたり、実行ログを開いたりできればいい。LAISORAは、そんな使い方から生まれたVS Code拡張機能です。

コマンドやファイル操作の記録は「状況」タブにまとめ、会話ではあなたの指示とエージェントの返答を追いやすくしています。下の2枚は同じターンで、1枚目が会話、2枚目が「状況」タブ側です。実行したコマンド、読み書きしたファイル、テスト、サブエージェントはすべて2枚目に並びます。

## 作業の記録を、次の改善につなげる

完成したものだけでは、AIが途中でどこにつまずき、何を繰り返していたのかは見えにくいものです。長いログを自分で読み解くのも簡単ではありません。

LAISORAでは、作業ログをLLMで分析し、進め方や指示、設定などの改善点を提案します。提案から根拠となった記録をたどり、納得できたものは、新しい会話で改善に取り組めます。

**LLMの進化を、日々の使い心地にも。**

分析にも会話で選んだモデルを使うことで、新しいモデルの能力を、作業の振り返りや改善提案にも活かせるようにしています。

## できること

### 複数の会話を並行して進める

会話は1つずつタブになります（既定20個。`laisora.tabLimit`）。タブごとに下書き・表示の選択・スクロール位置を保持し、メインの返答が終わってもサブエージェントやバックグラウンドのコマンドが動いている間はタブが点灯し続けます。過去の会話は履歴一覧から開き、会話を始めたフォルダで再開できます（途中のコマンドでフォルダを移動していても同じです）。既定では、ウィンドウを最後に閉じた・再読み込みしたときに開いていたタブを起動時に開き直します。新しいタブ1つで始めたい場合は`laisora.restoreTabsOnStartup`をオフにします（LAISORAの設定ページからも切り替えられます。設定ページは会話の☰メニューの「設定」か、コマンド「LAISORA: 設定を開く」で開きます）。

### 返答をノイズなしで読む

各タブには **会話** と **状況** の2つの表示があります。

会話には、主にモデルがあなたに向けて話した内容に加え、許可の確認、失敗、関連するシステム通知が表示されます。ツールの動き（Bash・PowerShellなどのコマンド実行、ファイルの読み書き、検索、サブエージェント、TODO）は状況側へ分離されるため、コマンドが何度続いても返答が細切れになりません。ツールを使ったターンが終わると、会話側に「✓ 作業完了 · N件 · 経過」のチップが出て、実行ログの該当箇所へ飛べます。

### エージェントが実際に何をしているかを見る

状況には4つのサブタブがあります。

- **概要** — セッション内の依頼ブロック、まだ動いているサブエージェントとバックグラウンドのコマンド、時間の内訳（LLM生成・ツール実行・LLM質問確認待ち・返信待ち）。
- **グラフ** — メインエージェント・サブエージェント・バックグラウンドタスクの時系列。時間窓を絞って見られます。サブエージェントを開くと、渡した指示の全文を読めます。
- **分析** — スクリプトによる集計と所見（失敗率、失敗ループ、サブエージェント比率、ターン時間）を自分の過去セッションと比較。任意でLLM分析を実行でき、所見から根拠へ辿れます。
- **実行ログ** — ツール呼び出しと、取得できた入力・出力のプレビュー、所要時間、失敗や規約違反の印。

記録が欠けている場合は取得できない情報があります。その場合、部分的な数字を確定値のように出さず、欠けていることを表示します。

### 実行中も手綱を離さない

ツール実行の許可・拒否は会話側で行います。状況側を見ているときに許可要求が来ると、会話タブが強調されて見落としません。実行中の追加指示、中断、会話内の検索（Ctrl+F）、モデル・effort（推論の強度）・権限モードの選択は、入力欄まわりの操作部から行えます。Enterで送信、Shift+Enterで改行です。`laisora.composer.sendKey`またはLAISORAの設定ページで入れ替えられます。

### 長い作業を次へ渡す

元の会話を残したまま、要約と取得したユーザー発言を使って新しい会話へ引き継げます。会話はMarkdownに書き出せます。対応するMarkdownファイルリンクからエディタの指定位置を開けます。対象はワークスペースまたは会話の作業ディレクトリの範囲内です。画像などテキストとして表示できないファイルは、その種類の既定のエディタで開きます。LAISORAをエディタのタブで開いているときは、リンク先のファイルをExplorerでも選択します（`laisora.fileLinks.revealInExplorer`）。サイドバーのLAISORAから押したときは、サイドバーは会話のまま切り替わりません。既定では、Claudeにローカルファイルをこの形式のリンクで書かせます（`laisora.claude.fileLinkInstruction`。会話を始めたとき・再開したときから有効で、実行中の会話には反映しません。会話の途中でシステムプロンプトを変えると、次の返答で会話全体を送り直すことになるためです）。ワークスペース外のファイルへのリンクを開くには、ユーザー設定の`laisora.fileLinks.allowOutsideWorkspace`をオンにします。既定では開く前に確認し、保存できない読み取り専用のエディターで開きます（`laisora.fileLinks.confirmOutsideWorkspace`・`laisora.fileLinks.openOutsideReadOnly`で変更できます）。ネットワーク共有（UNCパス）とデバイスパスは常に拒否し、リンクにもしません。これらの設定はLAISORAの設定ページからも切り替えられます。

## 前提要件

- VS Code 1.90以降。ローカルの信頼済みウィンドウで利用してください。

動作検証の対象はWindowsです。macOS・Linuxは未検証です。WSL、Remote SSH、Dev Containers、仮想ワークスペースには対応していません。

## インストールと起動

VS Codeのコマンドパレットで **Extensions: Install from VSIX…** を選び、配布された`.vsix`ファイルをインストールしてから、ウィンドウを再読み込みします。アクティビティバーのLAISORAアイコン、またはコマンドパレットの **LAISORA: Open** から開きます。

会話を始める前にプロジェクトのフォルダを開くか、既定の作業ディレクトリを設定してください。

主要な画面は英語と日本語に対応しています。一部の診断メッセージは日本語のままです。READMEの言語は冒頭のリンクから選べます。

## LAISORAの共通設定

送信キー、タブの復元、APIキーの扱い、ファイルリンクは、LAISORAの設定ページ（会話の☰メニューの「設定」、またはコマンド「LAISORA: 設定を開く」）で切り替えられます。タブ数の上限、既定の作業ディレクトリ、作業ログ分析などそのほかの設定は、VS Codeの設定画面で`laisora.*`を検索してください。拡張固有の設定や画面の状態はVS Code側に保存します。

## SDK別の設定と使い方

### Claude Agent SDK

#### 導入・認証

- Claude Codeをインストールし、自分のアカウントでログインしてください。LAISORAは既定で環境をそのまま渡します。`ANTHROPIC_API_KEY`が設定されているとClaude Codeはそれを使い、サブスクリプションではなくAPIに課金され、LAISORAは会話に通知を出します。`laisora.claude.apiKeyPolicy`を`subscriptionOnly`（ユーザー設定。LAISORAの設定ページからも切替可）にすると、起動する子プロセスからキーを除去し、サインイン済みのサブスクリプションを使います。継承されたClaude Code／Anthropicの環境変数や設定によって、認証や接続先が変わる場合があります。
- Claude CodeがJavaScript形式の起動ファイルを使う場合はNode.jsが必要です。ネイティブ実行ファイルを解決できる場合は、拡張側では不要です。

Claude Codeが見つからない場合は、ユーザー設定の`laisora.claude.executablePath`に実行ファイルまたはJavaScript起動ファイルのパスを指定します。ワークスペース設定からは指定できません。

#### 設定と実行権限

モデルとeffortは会話画面から選択できます。選択したモデルはClaude Code共通の`~/.claude/settings.json`へ保存され、以後のClaude Codeの会話にも影響します。effortは対応するモデルごとに保存し（Opus 1Mなど1Mコンテキスト版を含む）、新しい会話にも引き継がれます。`max`や保存先を特定できない場合は、そのセッション限りの指定になります。

effortの表示では、実行側が報告した値、会話での指定値、設定値を区別します。適用される値はClaude Codeの設定の優先順位やモデルの対応状況に従います。

LAISORA内で権限モードを変更しても、Claude Code共通の既定モードは書き換えません。選択は拡張側に保存しますが、`bypassPermissions`は次回用に保存しません。このモードを選ぶと、通常の許可確認なしでファイルの編集やコマンド実行が行われます。

#### 長い会話の引き継ぎと介入

会話の実行が終わったら、手動で引き継ぎを開始できます。元の会話を残し、要約と前回の引き継ぎ以降に取得したユーザー発言を使って、新しい会話へ続きを渡します。それ以前の文脈は、既存の要約と引き継ぎ記録を通じて受け継ぎます。引き継ぎにはモデルの利用枠を消費します。要約には抜けや誤解があり得るため、続きの会話で重要な条件を確認してください。

実行中のターンにも追加の指示を送れます。指示が渡されるタイミングはClaude Codeの処理の区切りに依存し、すぐに動作が変わるとは限りません。

Live Guardrailは、失敗の繰り返しなどを検知して出力に記録します。既定の自動介入は警告までで、設定により実行中のエージェントへ報告を送れます。自動で実行を中断する機能ではなく、ツール実行中の停滞やすべての背景プロセスを監視するものでもありません。

#### 履歴・データ送信・モデルの利用

LAISORAはClaude Codeのローカルな会話記録を読み、履歴や作業ログを表示します。拡張の状態や分析結果もローカルに保存します。分析結果は、LAISORAのVS Code拡張ストレージに実行1回につき1ファイルとして保存され、生成された所見や根拠のラベルを含むことがあります。会話・LLM分析・要約・引き継ぎでは、処理に必要な内容をClaude Code経由で送信し、アカウントの利用枠を消費します。作業ログの集計表示にはLLMを呼び出しません。

LLM分析の所見はモデルによる解釈です。引用や数値の検査を通っていても、判断全体の正しさを保証するものではありません。所見から根拠を確認できます。

Claude Codeの設定・hooks・ツールの構成は、実行内容や外部接続に影響します。Claude Codeを直接使うときと同様に確認してください。ログや保存した診断情報には会話の内容が含まれる場合があるため、共有前に内容を確認してください。

#### トラブルシューティング

- **会話を開始できない:** ターミナルで`claude`を起動し、ログインできているか確認してください。詳細は **表示 → 出力 → LAISORA** で確認できます。
- **作業ディレクトリがない:** フォルダを開くか、`laisora.defaultCwd`を設定します。過去の会話はその会話を始めたフォルダで再開するため、プロジェクトを移動した場合は元のパスを復元するか、新しい会話を始める必要があります。
- **利用上限や分析エラー:** 表示されたエラーとClaudeアカウントの利用状況を確認します。分析の失敗は、その会話に問題がないという判定ではありません。
- **追加指示がすぐ反映されない:** 再送する前に、その後の会話を確認してください。指示の搬送とモデルの応答は別の段階です。
