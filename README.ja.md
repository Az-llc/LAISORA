AIエージェントが次々とコマンドを実行し、コードを書き換えていく。そのログを眺めていても、何をしているのか、なぜ必要なのかまでは分からない。私自身、そんな場面が増えました。

それなら、普段は「何を実現したいか」「どう進めるか」の対話を読みやすくしたい。詳しく知りたいときは、エージェントに説明を求めたり、実行ログを開いたりできればいい。LAISORAは、そんな使い方から生まれたVS Code拡張機能です。

コマンドやファイル操作の記録はLOGにまとめ、CHATではあなたの指示とエージェントの返答を追いやすくしています。下の2枚は同じターンで、1枚目が会話の横にPLANとYOUを置いたCHAT、2枚目がLOGです。実行したコマンド、読み書きしたファイル、テスト、サブエージェントは2枚目に並びます。

## 作業の記録を、次の改善につなげる

完成したものだけでは、AIが途中でどこにつまずき、何を繰り返していたのかは見えにくいものです。長いログを自分で読み解くのも簡単ではありません。

LAISORAでは、作業ログをLLMで分析し、進め方や指示、設定などの改善点を提案します。提案から根拠となった記録をたどり、納得できたものは、新しい会話で改善に取り組めます。

**LLMの進化を、日々の使い心地にも。**

分析にも会話で選んだモデルを使うことで、新しいモデルの能力を、作業の振り返りや改善提案にも活かせるようにしています。

## できること

### 複数の会話を並行して進める

会話は1つずつタブになります（既定20個。`laisora.tabLimit`）。タブごとに下書き・表示の選択・スクロール位置を保持し、メインの返答が終わってもサブエージェントやバックグラウンドのコマンドが動いている間はタブが点灯し続けます。過去の会話は履歴一覧から開き、会話を始めたフォルダで再開できます（途中のコマンドでフォルダを移動していても同じです）。既定では、ウィンドウを最後に閉じた・再読み込みしたときに開いていたタブを起動時に開き直します。新しいタブ1つで始めたい場合は`laisora.restoreTabsOnStartup`をオフにします（LAISORAの設定ページからも切り替えられます。設定ページは会話の☰メニューの「設定」か、コマンド「LAISORA: 設定を開く」で開きます）。

### 返答をノイズなしで読む

各会話には、**CHAT**・**SUMMARY**・**GRAPH**・**ANALYSIS**・**LOG**の5つの表示を選ぶ縦のナビゲーションがあります。どの表示でも入力欄を使えます。

CHATには、モデルがあなたに向けて話した内容に加え、許可の確認、失敗、関連するシステム通知が表示されます。ツールの動き（コマンド実行、ファイルの読み書き、検索、サブエージェント）はLOGにまとまるため、コマンドが何度続いても返答が細切れになりません。返答は生成中も表示位置が跳ねずに読めます。各返答の末尾にはコピーボタンと日時があり、過去の返答ではマウスを重ねるかキーボードでフォーカスすると表示されます。自分の発言もコピーできます。

### エージェントが実際に何をしているかを見る

CHATの横にある**PLAN**には、エージェントが宣言した目標、手順とその状態、各手順の担当、経過時間、トークン数が表示されます。発言をまたいで目標全体を追い、完了した手順は件数つきの1行に畳まれ、開いて確認できます。手順の宣言がなければ、観測できた作業をNOWに表示します。狭いウィンドウでは、タイトル下の1行の帯からPLANとYOUの引き出しを開けます。

詳しく見たいときは、ほかの表示へ切り替えられます。

- **SUMMARY** — 左にPLAN、右にYOUを並べ、以前の依頼ごとの手順数・時間・トークン数を表示します。エージェント編成を有効にしていれば、観測できたエージェントと適用されたモデル・effortも表示します。狭いウィンドウではYOUを先にした1列になります。
- **GRAPH** — メインエージェント・サブエージェント・バックグラウンドタスクの時系列。時間窓を絞って見られます。サブエージェントを開くと、渡した指示の全文を読めます。
- **ANALYSIS** — 上部にTIME（メインエージェントのモデルごとの時間とツール実行の時間）、ROLES（委任先の役割ごとの時間とトークン数。行を開くと実行ごとの内訳）、ERR（ツール実行のうち失敗した数と種類）。その下に、LOGへ辿れる失敗の分類と規約違反を並べるスクリプト分析と、任意で実行できるLLM分析があり、LLM分析の所見は番号つきの記事として根拠へ辿れます。履歴一覧から過去のセッションを分析すると、自分の過去セッションとの比較も見られます。
- **LOG** — ツール呼び出しと、取得できた入力・出力のプレビュー、所要時間、失敗や規約違反の印。

記録が欠けている場合は取得できない情報があります。その場合、部分的な数字を確定値のように出さず、欠けていることを表示します。

### 実行中も手綱を離さない

**YOU**には、承認・判断・実機確認の依頼がまとまり、それぞれCHATで依頼された箇所へ戻れます。解決済みの項目は件数つきの1行に畳まれ、不要になった判断や確認は×で外せます。返答内の判断は、選択肢とその利点・難点、推奨、答えなかったときの既定の進め方を持つカードで表示されます。既定では、Claudeに計画の更新と、この形式での判断・確認の提示を求めます（`laisora.claude.planInstruction`。以後に開始・再開する会話から適用）。

ツール実行の許可・拒否はCHATで行います。実行中の追加指示、中断、会話内の検索（Ctrl+F）、モデル・effort（推論の強度）・権限モードの選択は、入力欄まわりから行えます。モデルのチップにはCLIが実際に適用するeffortを表示します。Enterで送信、Shift+Enterで改行です。`laisora.composer.sendKey`またはLAISORAの設定ページで入れ替えられます。

### エージェントの委任先を選ぶ

LAISORAの設定ページのエージェント編成で、worker・explorer・reviewerの役割と、行ごとのモデル・effortを設定できます（`laisora.orchestration.enabled`、`laisora.orchestration.agents`）。CLIがインストールされていれば、CodexとAntigravityを任意の外部実行役として使えます。編成の変更は次のセッションから適用されます。

### 学んだことを次の作業に残す

学習台帳は既定でオフです（`laisora.learning.enabled`）。有効にすると、メインエージェントがモデル固有または一般的な知見を記録でき、採用中のルールが後のセッションへ渡されます。記録は手元のマシンに保存し、絶対パスや認証情報を含む本文は受け付けません。エージェント編成の有無にかかわらず使え、設定変更は次のセッションから適用されます。

### 長い作業を次へ渡す

元の会話を残したまま、要約と取得したユーザー発言を使って新しい会話へ引き継げます。続きの会話は要約カードから始まり、記録された決定事項も引き継ぎます。会話はMarkdownに書き出すこともできます。

Markdownファイルリンクからエディタの指定位置を開けます。ワークスペースまたは会話のフォルダ内にあるOffice文書、PDF、そのほか指定した種類のファイルは既定のアプリで開きます（`laisora.fileLinks.openWithSystemApp`）。フォルダのリンクはファイルマネージャーで開きます。VS Codeで開くファイルは、LAISORAのエディタタブからリンクを押すとExplorerでも選択します（`laisora.fileLinks.revealInExplorer`）。サイドバーから押したときは会話の表示を保ちます。既定ではClaudeにローカルファイルをリンクで書かせます（`laisora.claude.fileLinkInstruction`。以後に開始・再開する会話から適用）。

ワークスペースと会話のフォルダの外にあるファイルを開くには、ユーザー設定の`laisora.fileLinks.allowOutsideWorkspace`をオンにします。既定では開く前に確認し、保存できない読み取り専用のエディタで開きます（`laisora.fileLinks.confirmOutsideWorkspace`・`laisora.fileLinks.openOutsideReadOnly`をオフにすると変更できます）。ネットワーク共有（UNCパス）とデバイスパスは常に拒否します。ファイルリンクの設定はLAISORAの設定ページからも変更できます。

## 対応SDK

| SDK | 対応状況 |
| --- | --- |
| Claude Agent SDK | 対応。ローカルのClaude Codeを通じて利用します。 |
| Codex SDK | 対応予定。現在のバージョンでは利用できません。 |

エージェント編成ではCodex CLIへの委任を任意で使えます。これはCodex SDKで会話を始める機能とは別です。

## 前提要件

- VS Code 1.90以降。ローカルの信頼済みウィンドウで利用してください。

動作検証の対象はWindowsです。macOS・Linuxは未検証です。WSL、Remote SSH、Dev Containers、仮想ワークスペースには対応していません。

## インストールと起動

VS Codeのコマンドパレットで **Extensions: Install from VSIX…** を選び、配布された`.vsix`ファイルをインストールしてから、ウィンドウを再読み込みします。アクティビティバーのLAISORAアイコン、またはコマンドパレットの **LAISORA: Open** から開きます。

会話を始める前にプロジェクトのフォルダを開くか、既定の作業ディレクトリを設定してください。

主要な画面は英語と日本語に対応しています。一部の診断メッセージは日本語のままです。READMEの言語は冒頭のリンクから選べます。

## LAISORAの共通設定

送信キー、タブの復元、APIキーの扱い、ファイルリンク、エージェント編成、学習のオン・オフは、LAISORAの設定ページ（会話の☰メニューの「設定」、またはコマンド「LAISORA: 設定を開く」）で変更できます。タブ数の上限、既定の作業ディレクトリ、作業ログ分析などそのほかの設定は、VS Codeの設定画面で`laisora.*`を検索してください。拡張固有の設定や画面の状態はVS Code側に保存します。

## SDK別の設定と使い方

### Claude Agent SDK

#### 導入・認証

- Claude Codeをインストールし、自分のアカウントでログインしてください。LAISORAは既定で環境をそのまま渡します。`ANTHROPIC_API_KEY`が設定されているとClaude Codeはそれを使い、サブスクリプションではなくAPIに課金され、LAISORAは会話に通知を出します。`laisora.claude.apiKeyPolicy`を`subscriptionOnly`（ユーザー設定。LAISORAの設定ページからも切替可）にすると、起動する子プロセスからキーを除去し、サインイン済みのサブスクリプションを使います。継承されたClaude Code／Anthropicの環境変数や設定によって、認証や接続先が変わる場合があります。
- Claude CodeがJavaScript形式の起動ファイルを使う場合はNode.jsが必要です。ネイティブ実行ファイルを解決できる場合は、拡張側では不要です。

Claude Codeが見つからない場合は、ユーザー設定の`laisora.claude.executablePath`に実行ファイルまたはJavaScript起動ファイルのパスを指定します。ワークスペース設定からは指定できません。

#### 設定と実行権限

モデルとeffortは、どの表示でも入力欄の横で選択できます。選択したモデルはClaude Code共通の`~/.claude/settings.json`へ保存され、以後のClaude Codeの会話にも影響します。effortは対応するモデルごとに保存し（Opus 1Mなど1Mコンテキスト版を含む）、新しい会話にも引き継がれます。`max`や保存先を特定できない場合は、そのセッション限りの指定になります。

モデルのチップには、Claude Codeの設定の優先順位やモデルの対応状況に従って適用されるeffortを表示します。詳細では、実行側が報告した値、会話での指定値、設定値を区別します。

LAISORA内で権限モードを変更しても、Claude Code共通の既定モードは書き換えません。選択は拡張側に保存しますが、`bypassPermissions`は次回用に保存しません。このモードを選ぶと、通常の許可確認なしでファイルの編集やコマンド実行が行われます。

#### 長い会話の引き継ぎと介入

会話の実行が終わったら、手動で引き継ぎを開始できます。元の会話を残し、要約と前回の引き継ぎ以降に取得したユーザー発言を使って、新しい会話へ続きを渡します。それ以前の文脈は、既存の要約と引き継ぎ記録を通じて受け継ぎます。引き継ぎにはモデルの利用枠を消費します。要約には抜けや誤解があり得るため、続きの会話で重要な条件を確認してください。

実行中のターンにも追加の指示を送れます。指示が渡されるタイミングはClaude Codeの処理の区切りに依存し、すぐに動作が変わるとは限りません。

Live Guardrailは、失敗の繰り返しなどを検知して出力に記録します。既定の自動介入は警告までで、設定により実行中のエージェントへ報告を送れます。自動で実行を中断する機能ではなく、ツール実行中の停滞やすべての背景プロセスを監視するものでもありません。

#### 履歴・データ送信・モデルの利用

LAISORAはClaude Codeのローカルな会話記録を読み、履歴や作業ログを表示します。拡張の状態や分析結果もローカルに保存します。分析結果は、LAISORAのVS Code拡張ストレージに実行1回につき1ファイルとして保存され、生成された所見や根拠のラベルを含むことがあります。会話・LLM分析・要約・引き継ぎでは、処理に必要な内容をClaude Code経由で送信し、アカウントの利用枠を消費します。作業ログの集計表示にはLLMを呼び出しません。

LLM分析の所見はモデルによる解釈です。引用や数値の検査を通っていても、判断全体の正しさを保証するものではありません。所見から根拠を確認できます。

Claude Codeの設定・hooks・ツールの構成は、実行内容や外部接続に影響します。Claude Codeを直接使うときと同様に確認してください。ログや保存した診断情報には会話の内容が含まれる場合があるため、共有前に内容を確認してください。

#### トラブルシューティング

- **会話を開始できない:** ターミナルで`claude`を起動し、ログインできているか確認してください。詳細は **表示 → 出力 → LAISORA** で確認できます。
- **作業ディレクトリがない:** フォルダを開くか、`laisora.defaultCwd`を設定します。過去の会話はその会話を始めたフォルダで再開するため、プロジェクトを移動した場合は元のパスを復元するか、新しい会話を始める必要があります。
- **利用上限や分析エラー:** 表示されたエラーとClaudeアカウントの利用状況を確認します。分析の失敗は、その会話に問題がないという判定ではありません。
- **追加指示がすぐ反映されない:** 再送する前に、その後の会話を確認してください。指示の搬送とモデルの応答は別の段階です。

## 開発の背景

LAISORA自身も、Claude Code・Codex・Antigravityとの対話を通じて開発しています。AIの作業ログを追いきれないという、開発中に感じた課題から生まれました。
